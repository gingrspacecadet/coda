# Chapter 2 - Your First Program

In the previous chapter, you learned what Coda is and the ideas that shaped its design.

Now it's time to write some code!

By the end of this chapter, you'll have created your first Coda project, compiled it, and ran your first executable.

---

## Installing Coda

Before you begin, you'll need the Coda compiler installed on your system.

Installation instructions for your operating system can be found the [Coda website](https://github.com/gingrspacecadet/coda)

Once installed, verify that the compiler is available by running:

```sh
coda --version
```

If the installation was successful, the compiler will print its version information.

You're now ready to create your first project!

---

## Creating a Program

A Coda program is made from one or more modules.

For this example, create the following directory structure:

```
hello/
└── src/ 
    └── main.coda
```

Change into the project directory:

```sh
cd hello
```

And open `src/main.coda` in your preferred editor.

Enter the following starter code:

```coda
module hello;

include std::debug = dbg;

@entry
fn none main() {
    dbg::println("Hello, world!");
}
```

Although this program is only a few lines long, it introduces several important ideas.

Let's look at them one-by-one.

---

## Modules

Every Coda source file belongs to exactly one module.

The first line of the file declares the module name.

```
module hello;
```

Modules provide namespaces for declarations and are the primary way of organising code in Coda.

You'll learn much more about modules later in this book.

---

## Including Modules

The next line imports the standard debugging module.

```
include std::debug = dbg;
```

This creates the alias `dbg`, allowing functions from `std::debug` to be accessed using the shorter name.

For example:

```
dbg::println("Hello, world!");
```

Without the alias, the function would instead be written as:

```
std::debug::println("Hello, world!");
```

Aliases are entirely optional, but they are often useful for long module names.

---

## Functions

The remainder of the file defines a function.

```coda
@entry
fn none main() {
    dbg::println("Hello, world!");
}
```

Functions perform work.

Every executable Coda program begins execution in a function marked with the `@entry` attribute. By convention, this function is usually named `main`.

The `fn` keyword begins a function declaration.

Immediately afterwards comes the return type:

```coda
fn none
```

The `none` type indicates that the function does not return a value.

Finally comes the function name:

```
main
```

followed by its parameter list.

This function accepts no parameters, so the parentheses are empty.

The statements enclosed by the braces form the function body.

---

## Exporting Declarations

```coda
@export
```

Declarations in Coda are private by default.

The `@export` attribute makes the following declaration visible outside of its module.

The program entry point must be exported so that the generated startup code can call it.

We'll cover attributes in much greater detail later in this book.

---

## Printing Text

Inside the function body is a single statement.

```coda
dbg::println("Hello, world!");
```

This calls the `println` function from the `std::debug` module.

Like most of Coda's functionality, `println` is provided by the standard library rather than being built into the language itself.

The string enclosed in quotation marks is passed to the function, which writes it to the terminal followed by a newline.

---

## Building the Project

To compile and run the project, run:

```sh
coda --run src/main.coda
```

If the build succeeds, the compiler will produce an executable for your platform, run it, then clean up any temporary artifacts (including the built executable).

As your projects grow, you'll use a build script to describe how they should be built. We'll cover build scripts later in the book.

Unlike interpreted languages, Coda produces native machine code ahead of time.

Once compilation has finished, no compiler or virtual machine is required to run the program.

---

## Expected Output

The program should print:

```
Hello, world!
```

Congratulations!

You're written, compiled, and executed your first Coda program.

---

## Experimenting

One ofthe best ways to learn a language is to modify working programs.

Before continuing to the next chapter, try making a few small changes.

Change the message:

```coda
dbg::println("Welcome to Coda!");
```

Add another call:

```coda
dbg::println("Hello, world!");
dbg::println("This is my first Coda program.");
```

Or create your own function:

```coda
fn none greet() {
    dbg::println("Greetings!");
}

@export
fn none main() {
    greet();
}
```

Don't worry if everything doesn't make complete sense yet.

Each chapter builds upon the last, gradually introducing new language features and explaining why they exist.

By the end of this book, programs much larger than this one will feel just as straightforward.

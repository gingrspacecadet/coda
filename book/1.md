# Chapter 1 - Welcome to Coda

Hello!

If you're reading this book, you're probably looking for a programming language that gives you complete control over your software, without forcing you to fight unnecessary complexity.

Coda is a statically typed systems programming language designed around explicitness, predictable performance, and compile-time programming. It is intended for everything, from command-line utilities to operating systems, game engines, compilers, and embedded software.

This book will teach you the language from first principles. No previous experience with Coda is needed!

---

## Why Coda?

Every programming language is a collection of trade-offs.

Some languages prioritise developer productivity over performance. Others prioritise safety, or portability, or backwards compatibility.

Coda was designed around a different question:

> *How can a systems programming language remain simple whilst still providing modern features?*

Over the last several decades, programming languages have accumulated many ideas. Some have proven extremely valuable:

- Strong static typing
- Generic programming
- Compile-time evaluation
- Powerful tooling
- Clear module systems

Others have often increased complexity without providing equivalent benefits:

- Hidden allocations
- Implicit function calls
- Multiple overlapping abstraction systems
- Large mandatory runtimes
- Implicit control flow

Coda attempts to keep the first group whilst avoiding the second.

---

## The Philosophy of Coda

Every feature in Coda exists because it supports one or more core principles.

### Explicitness

Operations that affect performance, memory, or control flow should be visible in the source code.

Memory allocation should never happen unexpectedly.

User-defined code should never execute implicitly.

Control flow should remain obvious when reading the program.

When something expensive happens, the source code should make that clear.

---

### Simplicity

Whenever possible, Coda prefers one powerful mechanism over several specialised ones.

For example, Coda does not have separate language features for optional values, result types, and tagged unions. Instead it provides inline sum types that can represent all of these concepts.

Similarly, methods are simply functions associated witha type, and interfaces are reusable collections of generic constraints.

The language grows by composing existing ideas rather than introducing new ones.

---

### Predictability

Reading code should be enough to understand what the compiler will generate.

The language avoids hidden work.

Features such as constructors, operator overloading, exceptions, and automatic memory management often introduce behaviour that is not immediately visible in the source code.

Coda deliberately avoids these mechanisms.

---

### Compile-Time Programming

Many problems are easier to solve during compilation that at runtime.

Coda provides compile-time evaluation and reflection as first-class language features.

Generating lookup tables, validation data, producing serialisers, or inspecting types can all be performed by the compiler, producing efficient native code without requiring external code generators.

---

### Zero-Cost Abstractions

High-level code should not imply slower code.

If an abstraction can be implemented without runtime overhead, it should be.

If runtime cost exists, it should be explicit.

---

### Libraries Before Language

Not every useful feature belongs in the language itself.

Whenever possible, functionality should be implemented as libraries built using existing language features.

Keeping the language small makes it easier to learn, easier to implement, and easier to reason about.

---

## What Coda Is Not

Understanding what Coda intentionally does *not* provide is just as important as understanding what it does.

Coda is not an object-oriented language.

It does not have classes, inheritance, or virtual methods.

Coda does not provide automatic memory management.

Programs manage memory explicitly using allocators.

Coda does not use exceptions for error handling.

Error are represented using sum types and propagated explicitly.

Coda does not rely in hidden constructors or destructors.

Initialisation and cleanup are performed explicitly by ordinary functions and language constructs such as `defer`.

These choices are deliberate. They keep programs predictable and keep the language focused on a small set of orthogonal concepts.

## A First Look

The traditional first program prints a short message to the terminal.

In Coda, it looks like this:

```coda
module hello;

include std::debug = dbg;

@export
fn none main() {
    dbg::println("Hello, world!");
}
```

Don't worry if every part of this program doesn't make sense yet.

Over the next few chapters, you'll learn:

- what modules are,
- how functions are declared,
- what `@export` means,
- how the standard library is organised, and
- how the compiler turns this source code into an executable program.

By the end of this book, every line of the program above will feel natural.

## Who This Book Is For

This book is intended for programmers who want to understand Coda from the ground up.

Experience with another programming language is helpful, but not required.

Whether your background is C, C++, Rust, Zig, Go, Java, Python, or something else entirely, the goal of this book is to explain not only *how* Coda works, but *why* it was designed this way.

Where useful, the book discusses the reasoning behind language features and the trade-offs involved in their design.

---

## What You'll Learn

By the time you finish this book, you will know how to:

- write complete Coda programs,
- design reusable libraries,
- use generics and constraints,
- perform compile-time computation and reflection,
- manage memory explicitly,
- interface with C libraries,
- build and distribute Coda packages, and
- write efficient systems software

This book follows a gradual progression.

Each chapter introduces a small number of new concepts before building upon them in later chapters.

The examples become larger over time, eventually culminating in complete, real-world programs.

# Chapter 3 - Variables and Basic Types

In the previous chapter, you wrote your first Coda program.

Now it's time to start working with data.

Every program stores information. A calculator stores numbers, a text editor stores text, and a game stores the positions of objects in the world.

In Coda, these values are stored in **variables**.

---

## Declaring Variables

A variable declaraation consists of three parts:

- a type,
- a name, and
- and optional initial value

For example:

```coda
int32 age = 21;
```

Here:

- `int32` is the variable's type,
- `age` is its name, and
- `21` is its initial value.

Once declared, the variable may be used like any other value.

```coda
dbg::println(age);
```

---

## Type Annotations

Unlike some languages, every variable in Coda has an explicit type.

```coda
uint64 population = 8_200_000_000;
bool enabled = true;
char letter = 'A';
string message = "Hello!";
```

The compiler always knows the type of every expression.

This helps catch mistakes early and makes code easier to understand.

Later in the book you'll see that Coda can infer some types - particularly generic arguments - but ordinary variable declarations always specify the type explicitly.

---

## Mutability

One of Coda's design principles is that values are immutable by default.

For example:

```coda
int32 count = 5;

count = 6;
```

This does **not** compile.

To alow a variable to be modified, mark it with the `mut` keyword.

```coda
mut int32 count = 5;

count = 6;
```

Now the assignment is valid.

Requiring mutability to be explicit makes accidental modification much less common.

When reading code, you immediately know which values may change over time.

---

## Integer Types

Coda provides fixed-width integer types.

Signed integers:

```
int8
int16
int32
int64
```

Unsigned integers:

```
uint8
uint16
uint32
uint64
```

Their sizes never depend on the target platform.

For example, an `int32` is always exactly 32 bits.

---

## Boolean Values

Boolean values represent truth.

There are only two possible values:

```coda
true
false
```

They are stored using the `bool` type.

```coda
bool connected = true;
```

---

## Characters

The `char` type represents a single 8-bit character.

Character literals use single quotation marks.

```coda
char initial = 'J';
```

Unlike strings, a character always represents exactly one byte.


---

## Strings

Strings represent sequences of characters.

String literals use double quotation marks.

```coda
string greeting = "Hello, world!";
```

You'll learn much more about strings in a later chapter.

For now, you can think of a string simply as text.

---

## Comments

Comments are ignored by the compiler.

Single-line comments begin with //.

```coda
// Print a friendly greeting.
dbg::println("Hello!");
```

Multi-line comments begin with /* and end with */.

```coda
/*
    This comment
    spans multiple
    lines.
*/
```

Comments are useful for explaining why code exists, rather than what it does.

Good code should usually explain itself.

---

## Putting It Together

Let's combine everything you've learned so far.

```coda
module hello;

include std::debug = dbg;

@entry
fn none main() {
    string name = "Alice";
    mut uint32 age = 24;
    bool programmer = true;

    dbg::println(name);
    dbg::println(age);
    dbg::println(programmer);

    age += 1;

    dbg::println(age);
}
```

Although this program is still small, it introduces most of the fundamental building blocks you'll use in every Coda program.

---

## Experimenting

Try modifying the program!

- Change the value of `name`.
- Create your own variables.
- Make a variable mutable, then modify it.
- Remove the `mut` keyword and see what error the compiler reports.
- Try assigning a string to an integer variable

Learning what *doesn't* compile is often just as valuable as learning what does.

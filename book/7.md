# Chapter 7 - Compound Types

So far, every value you've worked with has been a single piece of data.

An integer stores one number.

A boolean stores one truth value.

A character stores one byte.

Real programs, however, often need to work with groups of related values.

A pixel has a red, green, and blue component.

A file has a name, a size, and a modification time.

A game object has a position, velocity, and health.

Coda provides several compound types for representing collections of data.

In this chapter, you'll learn about arrays, slices, and structures.

---

## Arrays

An array stores a fixed number of values of the same type.

For example:

```coda
int32[5] scores;
```

This declares an array containing five 32-bit integers.

Unlike many languages, the array length is part of its type.

An `int32[5]` and an `int32[10]` are different types.

---

## Initialising Arrays

Arrays may be initialised when they are declared.

```coda
int32[5] scores = {
    12,
    18,
    25,
    31,
    42,
};
```

Each element occupies a fixed position within the array.

---

## Indexing

Individual elements are accessed using square brackets.

```coda
scores[0]
scores[1]
scores[2]
```

Array indices begin at zero.

The first element is at index `0`.

The second is at index `1`.

---

## Modifying Elements

If the array is mutable, its elements may also be modified.

```coda
mut int32[5] scores = {
    10,
    20,
    30,
    40,
    50,
};

scores[2] = 99;
```

After the assignment, the third element contains `99`.

---

## Array Length

Every array knows its length.

The `.len` member holds the number of elements.

```coda
dbg::println(scores.len);
```

This prints:

```text
5
```

Because the compiler knows the size of every array, this value is available at compile time.

---

## Slices

Arrays always have a fixed length.

Sometimes, however, the number of elements isn't known until runtime.

For this purpose, Coda provides **slices**.

```coda
int32[] values;
```

A slice refers to a sequence of values stored elsewhere.

Unlike an array, a slice does not own its data.

Instead, it provides a view over an existing sequence.

---

## Creating Slices

Slices are commonly created from arrays.

```coda
int32[5] scores = {
    10,
    20,
    30,
    40,
    50,
};

int32[] view = scores;
```

Both values refer to the same underlying data.

Modifying one affects the other.

---

## Structures

A structure combines several named values into a single type.

For example:

```coda
struct Player {
    string name;
    uint32 score;
    bool alive;
}
```

Each value stored inside the structure is called a field.

---

## Creating Structures

Once declared, structures behave like any other type.

```coda
Player player = {
    .name = "Alice",
    .score = 150,
    .alive = true,
};
```

This creates a new `Player` value.

---

## Accessing Fields

Fields are accessed using the `.` operator.

```coda
dbg::println(player.name);
dbg::println(player.score);
```

If the structure is mutable, individual fields may also be modified.

```coda
player.score += 50;
```

---

## Nesting Structures

Structures may contain other structures.

```coda
struct Vec2 {
    int32 x;
    int32 y;
}

struct Player {
    string name;
    Vec2 position;
}
```

Access simply continues using the `.` operator.

```coda
player.position.x
```

Large programs often build complex data by composing many small structures in this way.

---

## Putting It Together

Let's combine everything you've learned so far.

```coda
module game;

include std::debug = dbg;

struct Player {
    string name;
    uint32 score;
}

@entry
fn none main() {
    Player player = {
        .name = "Alice",
        .score = 0,
    };

    player.score += 100;

    dbg::println(player.name);
    dbg::println(player.score);
}
```

Although simple, this program introduces one of the most important ideas in programming: representing related data using your own types.

Almost every non-trivial Coda program will define structures.

## Experimenting

Try the following:

* Add another field to `Player`.
* Create two players instead of one.
* Create an array of players.
* Add a `Vec2` structure and store each player's position.
* Change the values and observe the output.

As your programs become larger, designing good data structures becomes just as important as writing good functions.

# Chapter 6 - Functions

The programs you've written so far have all placed their code inside a single function.

As programs grow, this quickly becomes difficult to manage.

Functions allow you to divide a program into smaller, reusable pieces, each responsible for one specific task.

Rather than writing the same code repeatedly, you can write it once and call it whenever it is needed.

---

## Declaring a Function

A function declaration begins with the `fn` keyword.

```coda
fn none greet() {
    dbg::println("Hello!");
}
```

This declares a function named `greet`.

Like `main`, it returns `none`, meaning it does not produce a value.

Unlike `main`, it is an ordinary function that may be called from elsewhere in the program.

---

## Calling a Function

Calling a function is as simple as writing its name followed by parentheses.

```coda
@entry
fn none main() {
    greet();
}
```

When the program reaches the call, execution temporarily moves into `greet`.

Once the function finishes, execution continues immediately after the call.

---

## Parameters

Functions often need information in order to perform their work.

This information is passed through **parameters**.

```coda
fn none greet(string name) {
    dbg::println(name);
}
```

The parameter declaration consists of a type followed by a name.

The function may use the parameter just like any other variable.

Calling the function now requires an argument.

```coda
greet("Alice");
```

The argument is copied into the function's parameter when the function is called.

---

## Multiple Parameters

Functions may accept any number of parameters.

```coda
fn int32 add(int32 left, int32 right) {
    return left + right;
}
```

Arguments are matched to parameters in the order they appear.

```coda
int32 total = add(10, 20);
```

---

## Returning Values

Functions may return values to their caller.

The return type appears immediately after the `fn` keyword.

```coda
fn int32 square(int32 value) {
    return value * value;
}
```

The `return` statement immediately ends the function and returns the specified value.

```coda
int32 result = square(6);
```

The value of `result` is now `36`.

---

## The `none` Type

Not every function needs to return a value.

Functions that exist only to perform an action use the `none` return type.

```coda
fn none print_separator() {
    dbg::println("----------------");
}
```

These functions simply finish executing when they reach the end of their body.

An explicit `return;` is also valid.

---

## Early Returns

A function may return before reaching its final statement.

```coda
fn none greet(string name) {
    if (name == "") {
        return;
    }

    dbg::println(name);
}
```

Early returns are often used to handle special cases before the main body of a function.

Doing so usually makes code easier to read by reducing unnecessary nesting.

---

## Functions Calling Functions

Functions may call other functions.

```coda
fn none greet(string name) {
    dbg::println("Hello");
    dbg::println(name);
}

fn none welcome(string name) {
    greet(name);
    dbg::println("Welcome to Coda!");
}
```

Breaking programs into small functions often makes them easier to understand than placing everything inside one large function.

---

## Designing Good Functions

A good function usually performs one task.

For example, instead of writing one function that loads a file, parses it, validates it, and displays the results, consider splitting it into several smaller functions.

Small functions are:

* easier to understand,
* easier to test,
* easier to reuse, and
* easier to modify.

As a general guideline, if a function becomes difficult to explain in a single sentence, it may be trying to do too much.

---

## Putting It Together

The following program demonstrates several functions working together.

```coda
module hello;

include std::debug = dbg;

fn none line() {
    dbg::println("================");
}

fn none greet(string name) {
    line();
    dbg::println("Hello!");
    dbg::println(name);
    line();
}

@entry
fn none main() {
    greet("Alice");
    greet("Bob");
}
```

Although still small, this program is already much easier to extend than placing every statement directly inside `main`.

## Experimenting

Try making the following changes:

* Add another parameter to `greet`.
* Write a function that multiplies two numbers.
* Create a function that returns a `bool`.
* Call the same function several times with different arguments.
* Split one large function into several smaller ones.

As programs become larger, good function design becomes increasingly important.

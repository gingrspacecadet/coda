# Chapter 8 - Memory and Pointers

Every value in a Coda program occupies memory.

So far, you've worked with variables without needing to think about where they are stored.

Most of the time, that's exactly how it should be.

Sometimes, however, you need to work with memory directly.

You may want to modify a large structure without copying it, implement a linked list, or interface with an operating system or C library.

For these situations, Coda provides pointers.

Understanding pointers begins with understanding memory.

---

## Values Live in Memory

Consider the following program.

```coda
mut int32 score = 42;
```

The variable `score` occupies a region of memory large enough to hold a 32-bit integer.

You normally work with the value itself.

```coda
score += 1;
```

The compiler automatically reads and writes the memory occupied by `score`.

You don't need to know its address.

Sometimes, however, you do.

---

## Taking the Address of a Value

The address-of operator (`&`) produces a pointer to a value.

```coda
mut int32 score = 42;

mut int32 *ptr = &score;
```

The variable `ptr` now refers to the same value stored by `score`.

Notice that `score` itself has not moved.

The pointer simply remembers where it lives.

---

## Dereferencing

A pointer can be used to access the value it points to.

This operation is called **dereferencing**.

```coda
*ptr = 100;
```

After this assignment, both expressions refer to the same value.

```coda
dbg::println(score);
dbg::println(*ptr);
```

Both print:

```text
100
```

A pointer does not contain the value itself.

It contains the address of the value.

---

## Pointer Types

Pointer types are written using the `*` suffix.

```coda
int32 *number;
Player *player;
char *text;
```

The type before the `*` specifies the type of value being pointed to.

Pointers to different types are themselves different types.

---

## Pointer Mutability

Pointers have two independent kinds of mutability.

The pointer itself may be mutable.

The value it points to may also be mutable.

For example:

```coda
int32 *a;
int32 mut *b;
mut int32 *c;
mut int32 mut *d;
```

These four declarations represent four different combinations of mutability.

This distinction allows Coda to precisely express whether a pointer may be redirected, whether the pointed-to value may be modified, or both.

---

## Optional Pointers

Not every pointer always refers to a value.

Sometimes the absence of a value is meaningful.

Optional pointers represent this possibility.

```coda
int32 *? number = null;
```

Before using an optional pointer, it must first be checked.

```coda
if (number != null) {
    dbg::println(*number);
}
```

Non-optional pointers can never be `null`.

This allows the compiler to eliminate unnecessary null checks in many situations.

---

## Pointer Arithmetic

Pointers may be advanced through contiguous memory.

```coda
int32[4] values = {
    10,
    20,
    30,
    40,
};

int32 *ptr = &values[0];

ptr += 1;
```

The pointer now refers to the second element of the array.

Unlike C, pointer arithmetic in Coda is bounds checked by the compiler whenever possible.

A pointer may never leave the object it was derived from.

Attempting to move beyond the end of the array is an error.

This prevents an entire class of bugs before the program is ever run.

---

## Arrays and Pointers

Although related, arrays and pointers are different types.

```coda
int32[4] values;
```

stores four integers.

```coda
int32 *ptr;
```

stores one address.

Arrays do not automatically decay into pointers.

If you need a pointer to the first element, take it explicitly.

```coda
int32 *ptr = &values[0];
```

Making this conversion explicit avoids surprising behaviour and preserves type information.

---

## Passing by Pointer

Large values are often passed by pointer rather than by value.

```coda
struct Player {
    string name;
    uint32 score;
}

fn none level_up(mut Player *player) {
    player.score += 100;
}
```

The function modifies the original value rather than a copy.

This is both more efficient and makes the programmer's intent explicit.

---

## Putting It Together

```coda
module pointers;

include std::debug = dbg;

struct Counter {
    uint32 value;
}

fn none increment(mut Counter *counter) {
    counter.value += 1;
}

@entry
fn none main() {
    mut Counter counter = {
        .value = 0,
    };

    increment(&counter);

    dbg::println(counter.value);
}
```

Pointers allow functions to operate directly on existing values rather than creating unnecessary copies.

They are one of the fundamental tools of systems programming.

## Experimenting

Try the following:

* Create a pointer to an integer.
* Modify the value through the pointer.
* Create a structure and pass it to a function by pointer.
* Try assigning `null` to a non-optional pointer.
* Experiment with pointer arithmetic on an array.

Observe which programs compile and which do not.

The compiler's error messages are an important part of learning the language.
